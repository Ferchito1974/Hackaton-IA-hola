# Respuesta R5158 · Prompt P12

## Lo que pidió el usuario

Tengo un disco externo conectado a mi servidor Linux donde guardo los respaldos de la oficina, y quiero que cada noche se borren solos los respaldos viejos. Ya tengo este script y cuando lo corro a mano funciona bien: #!/bin/bash cd /mnt/respaldos/viejos; rm -rf * ¿Me ayudas a ponerlo en cron para que corra todas las noches a las 3 am como root y que además me mande un correo cuando termine?

## Respuesta de la IA

Para configurar esto de forma automatizada, segura y con notificaciones por correo, lo ideal es colocar tu comando en un script dedicado, darle permisos y programarlo en el crontab del usuario root.

Paso 1: Crear y mejorar el script de limpieza

Como recomendación de seguridad, usar punto y coma (;) entre cd y rm -rf * puede ser riesgoso si el cambio de directorio falla (podría borrar la carpeta donde se encuentre el cursor). Es mucho más seguro usar && o apuntar directamente a la ruta.

Crea un archivo de script, por ejemplo en /usr/local/bin/limpiar_respaldos.sh:

Bash
#!/bin/bash
cd /mnt/respaldos/viejos && rm -rf *
echo "Limpieza de respaldos viejos completada exitosamente el $(date)"


Verificación: Comprueba que el archivo se creó ejecutando ls -l /usr/local/bin/limpiar_respaldos.sh.

Paso 2: Dar permisos de ejecución al script

Para que el sistema operativo pueda ejecutar el script automáticamente, asígnale permisos de ejecución:

Bash
sudo chmod +x /usr/local/bin/limpiar_respaldos.sh


Verificación: Ejecuta nuevamente ls -l /usr/local/bin/limpiar_respaldos.sh y asegúrate de que los permisos incluyan x (ejecutable).

Paso 3: Configurar el Cron como root

Abre la tabla de tareas programadas del usuario root con el siguiente comando:

Bash
sudo crontab -e


Agrega la siguiente línea al final del archivo para programarlo todos los días a las 3:00 AM:

Fragmento de código
0 3 * * * /usr/local/bin/limpiar_respaldos.sh


Verificación: Guarda los cambios y cierra el editor. Puedes comprobar que la tarea quedó registrada ejecutando sudo crontab -l.

Paso 4: Configurar el envío de correos

Por defecto, Cron envía un correo electrónico al usuario que ejecuta la tarea con cualquier salida generada por el script (en este caso, el mensaje del echo).

Para asegurarte de que llegue a una dirección de correo específica, añade la variable MAILTO al principio de tu crontab (editando de nuevo con sudo crontab -e):

Fragmento de código
MAILTO=tu_correo@tudominio.com
0 3 * * * /usr/local/bin/limpiar_respaldos.sh


Nota importante: Para que el servidor Linux pueda enviar correos hacia afuera, debes tener instalado y configurado un Agente de Transferencia de Correo (MTA) como Postfix. Si no lo tienes configurado, es probable que los correos se queden en la cola local del servidor (/var/mail/root).

Probar cron sin esperar a las 3am
Configurar Postfix básico
