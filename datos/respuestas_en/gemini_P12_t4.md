To set this up in an automated, secure and with email notifications, best place your command in a dedicated script, give permission and program it at the root user's crontab.

Step 1: Create and improve the cleaning script

As a safety recommendation, using point and coma (;) between cd and rm -rf * can be risky if directory change fails (you could clear the folder where the cursor is). It's far safer to use & & or aim directly at the route.

Create a script file, for example at / usr / local / bin / clear _ backup:

Bash
#! h
cd / mnt / backups / old & rm -rf *
echo "Old back clearance successfully completed the $(date)"


Verification: Check that the file was created by running ls -l / usr / local / bin / clear _ backup.

Step 2: Give performance permits to script

To allow the operating system to run the script automatically, send them run permits:

Bash
sudo chmod + x / usr / local / bin / clear _ backup. sh


Verification: Rerun ls -l / usr / local / bin / clear _ back.sh and make sure that permissions include x (executable).

Step 3: Configure the Cron as root

Open the Root user's scheduled task table with the following command:

Bash
sudo crontab -e


Add the following line at the end of the file to schedule every day at 3: 00 AM:

Code fragment
0 3 * * * / usr / local / bin / clear _ backup. sh


Verification: Save the changes and close the editor. You can check that the task was registered by performing sudo crontab -l.

Step 4: Configure Email Sending

By default, Cron sends an email to the user that runs the task with any output generated by the script (in this case, the echo message).

To make sure you get to a specific email address, add the MAILTO variable at the beginning of your crontab (editing again with crontab-e sudo):

Code fragment
Mailto = your _ mail @ tudominio.com
0 3 * * * / usr / local / bin / clear _ backup. sh


Important note: To get the Linux server to send emails out, you have to have an Email Transfer agent (MTA) as Postfix installed and set up. If you have no set up, the emails are likely to stay at the local server's (/ var / mail / root) tail.
